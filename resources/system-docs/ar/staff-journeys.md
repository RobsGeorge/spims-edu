## نظرة على رحلات الموظفين

يُنظَّم عمل الموظفين حسب المراكز. بوابات الأدوار تحدّد ظهور المراكز؛ وداخل كل مركز تحدّد مفاتيح الصلاحيات البلاطات والإجراءات.

---

## مركز التدريس (المدرّس والمساعد)

يفتح المدرّسون والمساعدون **التدريس** من الشريط الجانبي (أو الشريط السفلي للجوال عند القدرة على التدريس). يسرد المركز العروض التي يعملون عليها.

لكل عرض يمكنهم:

| المجال | ماذا يفعلون |
|---|---|
| **المحتوى** | بناء أسابيع وعناصر (فيديو، قراءة، نص، واجب، اختبار، امتحان، نقاش) |
| **التقييمات** | بنوك أسئلة، ربط أسئلة، إنشاء اختبارات/امتحانات، إصدار النتائج، تجاوز الدرجات |
| **دفتر الدرجات** | مكوّنات موزونة؛ بذر من قالب؛ إدخال درجات؛ **إرسال**؛ **قفل** (المدرّس فقط) |
| **المباشر** | جدولة Zoom (يمنع النظام التداخل — يُفترض ترخيص مضيف واحد)؛ استيراد أو تجاوز الحضور |
| **النقاشات** | ضبط اللوحة، إشراف على الخيوط، تقييم المشاركة |
| **الإعلانات** | نشر تحديثات تظهر في مشغّل المقرر |
| **قائمة الطلاب** | عرض الملتحقين؛ تصدير/إعلان حيث يُسمح |
| **مشاريع / تغذية راجعة / اختبار مباشر** | حيث مفعّلة للعرض (أسطح S6E) |

**قفل الدرجات** ينشر سجلات رسمية للكشف. المساعد لا يقفل. فقط **المدير الأكاديمي** يمكنه **إعادة فتح** دفتر مقفل.

### تدفق تدريس نموذجي

1. فتح التدريس → اختيار عرض.
2. بناء أو تعديل محتوى الأسابيع والبوابة.
3. ضبط التقييمات وأوزان دفتر الدرجات (مجموع 100%).
4. جدولة الجلسات المباشرة؛ إدارة الحصة؛ استيراد الحضور.
5. تصحيح التسليمات؛ اختياريًا اقتراحات مقال بالذكاء الاصطناعي.
6. المدرّس يُرسل ثم **يقفل** دفتر الدرجات.
7. إن لزم تصحيح بعد القفل → المدير الأكاديمي يعيد الفتح → المدرّس يعيد القفل.

## المدير الأكاديمي — مكتب المناهج

يستخدم المديرون الأكاديميون مركز **الأكاديميا** (بوابة `programs.manage`).

| البلاطة / المجال | الغرض |
|---|---|
| البرامج | دبلوم/شهادة/درجة؛ سقوف ساعات وفصول؛ اختيارية؛ عتبة النجاح؛ موقّع الشهادة |
| المقررات | ساعات معتمدة، أسعار افتراضية دولار/جنيه، مجاني/مستقل، متطلّبات، عدّادات اهتمام |
| العروض | ربط مقرر بفصل (دفعة) أو ذاتي الوتيرة؛ مقاعد؛ عتبة حضور؛ طاقم (مدرّس/مساعد)؛ أسعار إقليمية |
| الفصول / السنوات | التقويم ونوافذ التسجيل (غالبًا مشتركة مع الإدارة) |
| قوالب التقييم | مخططات دفتر درجات افتراضية |
| مخططات الدرجات | نطاقات حروف، نسب، نقاط معدّل، علامة نجاح |
| الترجمات | نص بشري أو بمساعدة ذكاء اصطناعي؛ التحقق قبل الاستخدام |
| الوثائق | إصدار أو إعادة توليد كشوف وشهادات |
| الإرشاد / التقارير / الاستبيانات | مكتب إرشاد، تقارير أكاديمية، استبيانات موظفين |

## إدارة المدرسة — قبول، مستخدمون، مظهر

يستخدم المديرون الإداريون مركز **الإدارة** (بوابة `users.manage`).

| المجال | ماذا يفعلون |
|---|---|
| **المستخدمون** | إنشاء وإيقاف الحسابات؛ تعيين الأدوار |
| **نماذج الطلب** | أنواع الحقول، الإلزام، رفع المستندات |
| **طابور الطلبات** | تصفية بالحالة؛ قبول/رفض/انتظار مع ملاحظات؛ **تسجيل** المقبولين في البرنامج |
| **إدارة التسجيل** | تجاوز الالتحاق، قوائم انتظار، وضع أو رفع **حجوزات مالية** |
| **محرّر المظهر** | اسم المدرسة، شعارات فاتح/داكن، أيقونة، ألوان، معاينة حيّة |
| **نظام المساعدة** | فئات ومقالات Help داخل التطبيق (ليست وثائق النظام هذه) |
| **فعاليات / اتصالات** | فعاليات المدرسة وتقارير الاتصال حيث مفعّلة |

### تدفق قبول نموذجي

1. بناء أو تحديث نموذج الطلب للدورة.
2. الطلاب يُرسلون → الطابور يظهر قيد المراجعة.
3. قرار قبول / انتظار / رفض مع ملاحظات.
4. تسجيل المقبولين في البرنامج.
5. الطالب يلتحق بالعروض وفق النوافذ والمقاعد والحجوزات.

## الإدارة المالية

يعمل المديرون الماليون (بوابة `offerings.pricing` لمكتب المالية) من بلاطات إدارة مركز **المالية**؛ ويظل كل المستخدمين يرون أدوات المحفظة الشخصية.

| المهمة | التفاصيل |
|---|---|
| التسعير | أسعار العروض وتجاوزات إقليمية (حسب البلد) |
| طابور الفواتير | فواتير الالتحاق؛ إنشاء فواتير يدوية |
| مدفوعات يدوية | تسجيل والتحقق من نقد / تحويل / شيك |
| الاستردادات | موافقة؛ العودة لمحفظة الطالب |
| المحفظة | منح نقاط أو شحن مال (أرصدة جنيه/دولار منفصلة) |
| التقارير | أرصدة مستحقة وإيراد مدفوع، مفصولان دولار وجنيه |
| التبرعات | من لديه صلاحية يمكنه التبرع؛ المالية تشرف |

المال دائمًا **وحدات صغرى صحيحة** (سنتات / قروش). بلا كسور عائمة؛ بلا تحويل عملة تلقائي.

## المشرف الأعلى — مستوى التحكّم

يفتح المشرفون الأعلى **المشرف الأعلى** لعمليات المنصة:

| القسم | المحتوى |
|---|---|
| **الأشخاص** | اختصار للمستخدمين |
| **الوصول** | مركز الأدوار (تجاوزات المصفوفة)، الأمن (مثل مسح الجلسات) |
| **المظهر** | محرّر المظهر |
| **المدرسة** | اختصارات للأكاديميا والمالية والوثائق والقبول والتسجيل والتقارير |
| **الأدلة** | سجل التدقيق، المراقبة (طوابير، مهام فاشلة، نسخ احتياطي)، الصحة |
| **التشغيل** | مهام مجدولة، اختبارات نظام، كشف هويات التغذية الراجعة |

كل كتابة مهمة (التحاق، دفع، قفل درجات، قرار قبول، وما شابه) تُسجَّل عبر `AuditLogWriter`. المشرف الأعلى يتجاوز فحوصات الصلاحيات؛ المفاتيح ذات الخرائط الفارغة (مثل `features.manage`، `roles.manage_matrix`) تبقى للمشرف الأعلى فقط ما لم يمنحها مركز الأدوار.

## أمثلة تعاون عبر الأدوار

| السيناريو | من يعمل |
|---|---|
| طالب محجوب بحجز مالي | المدير المالي أو الإداري يرفع الحجز → الطالب يلتحق/يدفع |
| درجة مقفلة تحتاج تصحيحًا | المدير الأكاديمي يعيد الفتح → المدرّس يصحّح → يعيد القفل |
| إعداد فصل جديد | أكاديمي: عروض وطاقم؛ إداري: نماذج ونوافذ؛ مالي: أسعار |
| شهادة بعد الإكمال | أكاديمي أو إداري يُصدر → الطالب يشارك رابط التحقق العام |
